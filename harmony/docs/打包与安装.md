# 打包与安装 · 草记 鸿蒙原生版

> 目标：从这份源码得到一台华为手机上能点开的 `草记`。
> 全文按「最短路径优先」写，赶时间只看第 1 节。

---

## 0. 先说清楚：为什么源码里没有现成的 .hap

`.hap` 不是压缩包改后缀就能用的东西。它里面这几样必须由 HarmonyOS SDK 的编译链生成：

| 内容 | 由谁生成 | 缺了会怎样 |
|------|---------|-----------|
| `ets/modules.abc` | SDK 里的 ArkTS 编译器（ets-loader → es2abc） | 整个应用没有可执行逻辑。`@Component` / `build()` 是 ArkUI 的方言，标准 TypeScript 编译器不认，无法手工转 |
| `resources.index` | SDK 里的 `restool` | 资源全部按 id 索引查找，没有 index 就取不到任何字符串/颜色/图片 |
| `module.json` | `module.json5` 经编译 | 系统靠它识别能力、权限、页面入口 |
| `pack.info`、签名块 | 打包与签名工具 | 无签名 = 装不上 |

所以必须借助 DevEco Studio（或它的命令行工具）在**你这台机器上**编译一次——这一步没有任何脚本能代劳，因为它需要 SDK 本体（约 3~8 GB，随 DevEco 一起装）。

本仓库能做的，是把编译**之后**的所有手工活（找 SDK、拼命令、收产物、签名、装机）全部自动化。

## 1. 最短路径（Grind：DevEco 图形界面，约 10 分钟）

1. **装 DevEco Studio 5.0**（官网下载，安装时勾上 HarmonyOS SDK，默认会拉 API 12）
2. **打开工程**：`File → Open` 选 `CaojiHarmony` 目录 → 等右下角 **Sync** 跑完（首次要下依赖，几分钟）
3. **配签名**：`File → Project Structure → Signing Configs` → 勾 **Automatically generate signature** → 登录华为账号 → OK
4. **连手机**：手机开「开发者模式 + USB 调试」→ 数据线连电脑 → DevEco 顶部设备列表里能看到机型
5. **出包**：菜单 `Build → Build Hap(s)/APP(s) → Build Hap(s)`

产物在：

```
entry\build\default\outputs\default\entry-default-signed.hap
```

同一个目录里的 `entry-default-unsigned.hap` 是没签名的，**装不上**，别拿错。
（用第 2 节的脚本跑会自动挑 signed 的并复制到 `out\`，文件名带时间戳，便于区分。）

## 2. 命令行打包（脚本已备好）

前置：第 1 节的第 1、2、3 步至少做过一次（Sync 过才会生成 `hvigorw.bat`）。

```powershell
cd C:\Users\simon\Desktop\CaojiHarmony
powershell -ExecutionPolicy Bypass -File tools\build-hap.ps1 -Release
```

脚本会依次做：找 DevEco → 找 SDK（并设 `DEVECO_SDK_HOME`）→ 用 DevEco 自带 Node → 调 hvigor `assembleHap` → 把产物复制到 `out\` 并打印大小与 sha256。

参数：

| 参数 | 作用 |
|------|------|
| `-Release` | release 构建（默认 debug） |
| `-Clean` | 先 `clean` 再构建 |
| `-DevEco "D:\Huawei\DevEco Studio"` | 装在非默认路径时指定 |

如果脚本报「没找到 hvigorw.bat」：说明工程还没被 DevEco 打开过，先做第 1 节第 2 步。

## 3. 签名：两条路，二选一

华为的 hap 必须签名才能装。签名不是加密，是「证明这份包是你发的」，所以材料只能来自你自己的华为账号。

### 路线 A：自动签名（推荐，最快）

DevEco 里点一下「Automatically generate signature」，它会自动生成 `.p12` 密钥库、去 AGC 领 `.cer` 与调试用 `.p7b`，并写进 `build-profile.json5` 的 `signingConfigs`。

优点：零配置；缺点：必须登录账号，且签出的调试包**只能在已注册的调试设备上装**（默认限 100 台，可在 AGC 里管理）。

### 路线 B：离线签名（不想登录 / 要给别人装）

需要 4 样东西：

| 材料 | 怎么来 |
|------|--------|
| `.p12` 密钥库 + `keyAlias` | DevEco：`Build → Generate Key and CSR`；或 `keytool -genkeypair` |
| `.cer` 应用证书 | AGC →「证书、APP ID 和 Profile」→ 证书 → 新增 → 下载 |
| `.p7b` Profile | 同一页 → Profile → 新增（选 release 或 debug）→ 下载 |

然后把它们填进配置并签名：

```powershell
copy tools\sign-config.sample.json tools\sign-config.json
notepad tools\sign-config.json           # 填 4 个路径 + 2 个密码
powershell -ExecutionPolicy Bypass -File tools\sign-hap.ps1
```

脚本用 SDK 自带的 `hap-sign-tool.jar` 做 `localSign`，等价于这条命令：

```
java -jar hap-sign-tool.jar sign-app \
  -keyAlias caoji -signAlg SHA256withECDSA -mode localSign \
  -appCertFile caoji.cer -profileFile caoji.p7b \
  -inFile entry-default-unsigned.hap -outFile caoji-signed.hap \
  -keystoreFile caoji.p12 -keyPwd *** -keystorePwd ***
```

> **最容易踩的坑**：`.p7b` 里的 `bundleName` 必须与 `AppScope/app.json5` 的 `online.wokaka.caoji` 完全一致。包名改了却没重建 Profile，签出来的包一定装不上，报错还很难懂（见下表 9568289）。
> 另外 `release` 类型的 Profile 才能上架；`debug` 类型只能装到 AGC 里登记的调试设备。

## 4. 安装到手机

准备：手机「设置 → 关于手机」连点版本号 7 次 → 开发者选项 → 打开 **USB 调试**；插线后手机上点「允许调试」。

```bash
hdc list targets                       # 应看到设备序列号
hdc install -r out\caoji-1.18.0-release-signed-20261022-2230.hap
hdc shell aa start -a EntryAbility -b online.wokaka.caoji   # 可选：直接拉起
```

`hdc` 在 `DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe`，或 `%LOCALAPPDATA%\Huawei\Sdk\...\toolchains\`。

也可以直接在 DevEco 里按绿色三角 Run，它做完编译+签名+安装+拉起。

## 5. 报错对照表

| 现象 | 原因 | 处理 |
|------|------|------|
| `install failed due to grant request permissions failed` (9568289) | 签名不匹配：Profile 的 bundleName / 证书 / 设备三者对不上 | 核对 bundleName；debug Profile 只能装登记的调试机；重新走自动签名 |
| `error: failed to install bundle. code:9568320` | 包名冲突或已装同包名不同签名版本 | 先 `hdc uninstall online.wokaka.caoji` |
| `compileSdkVersion 12 not found` | 本地 SDK 版本与 `build-profile.json5` 的 `candidateSdkVersion` 不一致 | 把 `build-profile.json5` 的 `compatibleSdkVersion` 改成你实际装的版本 |
| `Cannot find module '@kit.XXX'` | SDK 版本太老，没有该 Kit | SDK Manager 升级到 API 12 及以上 |
| 编译通过但一开就闪退 | 多半是某个 `@kit` API 在真机上抛异常被 catch 吞掉 | `hdc hilog | grep caoji` 看日志；本工程大量 `catch` 只提示不中断 |
| 切后台 30 秒后录音断 | `module.json5` 缺 `backgroundModes` 或用户没允许后台运行 | 本工程已声明 `["audioRecording"]`；检查系统「应用启动管理」里允许后台活动 |
| 蓝牙耳机连上不自动录 | 未授予蓝牙权限 / 自动记录开关关着 / 耳机只连了 HFP 未连 A2DP | 设置页看「自动记录」；确认耳机已配对且在系统里显示为已连接 |

## 6. 产物里到底有什么

```
caoji-xxx-signed.hap  (zip 结构)
├─ module.json            能力、权限、页面入口（系统读这个）
├─ ets/modules.abc        ArkTS 编译后的字节码（你的全部逻辑）
├─ resources.index        资源索引表
├─ resources/             图片、字符串、颜色
├─ libs/arm64-v8a/*.so    原生库（本工程未使用，可空）
├─ pack.info              打包元信息
└─ (META-INF 签名块)      证书链与 Profile，装机时校验
```

想自己验一下签没签成功，可以改名成 `.zip` 解开看有没有签名块——但**不要**改完再改回去当 hap 用，签名会失效。
