<h1 align="center">草记</h1>

<p align="center">
  戴上耳机就开始记 —— 把日常沟通变成可检索、可跟进的记录
</p>

<p align="center">
  <b>持续记录 → 自动转写 → 拆分事件、生成摘要与待办 → 跨场景项目归集 → 行为觉察</b>
</p>

两个刻意的取舍：
- **触发机制**：**手机连上蓝牙耳机后**才开始记录（不用手动开关，也避免 24 小时乱录）
- **通话覆盖**：通过读取手机自带「通话录音」文件，把**来电/去电通话内容**纳入记录（微信语音见下方说明）

## 一、先看能力边界（很重要）

| 需求 | 是否可行 | 说明 |
|------|---------|------|
| 蓝牙耳机连接触发录音 | ✅ 可以实现 | 监听 HFP/A2DP 连接广播 |
| 现场对话记录 | ✅ 可以实现 | 麦克风录音（耳机麦克风或手机麦克风） |
| **来电/去电通话内容** | ⚠️ **间接实现** | Android 10 起第三方 App **无法**录制通话音频（`VOICE_CALL` 源已移除）。本 App 通过**读取系统自带「通话自动录音」生成的文件**实现——需手机系统支持通话录音（ColorOS 支持） |
| **微信语音通话内容** | ❌ **无法实现** | 微信语音不经系统通话通道，且微信会主动静音内录通道；屏幕录制同样录不到。这是全行业限制（录音笔、Plaud 等也同样做不到） |
| 转写 + 摘要 + 待办提取 | ✅ 可以实现 | 接云端 ASR + 大模型 |
| 项目归集 / 行为洞察 | ✅ 可以实现 | 大模型分类 + 本地统计 |

> 如果系统通话录音文件拿不到（例如 ColorOS 未开启通话自动录音），App 依然可用：现场对话正常记录，通话部分只能靠录音笔/另一台设备补录。

**合规提醒**：录音涉及他人声音，请遵守《个人信息保护法》《民法典》相关规定——建议开启系统通话录音的提示音、明确告知对方、仅作个人工作记录，不得用于非法目的或公开传播。

| **短按打标 → 时间线定位** | 记录重点的时间点（03:15、07:42），详情页与列表都显示处数 | `RecorderService.markPoint()`、`Session.marks` |

| **觉察：跨记录行为复盘** | 汇总近 30 天记录，输出「沟通模式 / 盲区 / 值得保持 / 下周可试」 | `ui/InsightFragment.kt`、`ai/LlmClient.retrospect()` |

| 只留文字不留原音 | 转写完成后自动删除音频（可在设置改为保留） | `AnalysisPipeline` + `K_KEEP_AUDIO` |
| 通话录音纳入记录 | 扫描系统通话录音 → 导入 → 转写分析 | `audio/CallRecordingScanner.kt` |

## 三、版本演进（v1.1 → v1.24）

每个版本只解决一个被指出来的具体问题，没有一版是「顺手重构一下」。

| 版本 | 解决的问题 | 技术要点 |
|---|---|---|
| v1.1 | 界面粗糙、录完才知道录了什么、AI 摘要跑题 | 设计 token 收口（间距 / 圆角 / 字阶一处改全局）；录音后离线音频分析（底噪 + 人声占比 + 峰值判四类场景，纯噪音不入库）；摘要三层治理：转写清洗 → 长文 map-reduce → **数字须在原文可查、待办找不到依据即丢弃** |
| v1.2 | 界面不像 ColorOS 原生 | 按 Aquamorphic 语言定尺度：22dp 卡片圆角、52dp 胶囊按钮、24sp 页标题、20dp 页边距；`values-night` 全套深色 + DayNight 主题 |
| v1.3 | 更名「草记」，需要一个能进桌面的图标 | 自适应图标：矢量前景 `ic_launcher_foreground` + 底色 `ic_launcher_bg`，圆 / 超椭圆 / 圆角方三种遮罩都不裁切字形 |
| v1.5 | 每段录音都要手点「我是说话人几」 | 本地 25 维声纹（12 维 MFCC + 一阶差分 + 基频）：**中心化余弦**放大个体差距（不同人约 0.09，音色接近约 0.004），logistic 换算成匹配度，≥80% 才自动采用；不联网、不上传声音 |
| v1.6 | 耳机明明连着却显示断开，录音被自己停掉 | 根因是**把 CONNECTING / DISCONNECTING 中间态当成断开**。改为只认终态 + 断开宽限 3 秒（期间恢复则撤销）+ 连接去抖 0.5 秒 + 按设备地址集合记录 + 回前台主动校正 + SCO 用完必释放 |
| v1.7 | 配色花、耗电快 | 灰承担结构、正红只承担强调；耗电逐条掐：通知改 `setUsesChronometer` 由系统渲染（1 小时 3600 次 → 0）、列表只在状态变化时刷新（每分钟 60 次 → 每段 2 次）、环境分析只解码前 3 分钟、声纹只跑目标说话人且每人 ≤90 秒、码率 128 → 64kbps |
| v1.8 | 没有质感、点卡片没反应、录完卡死或自动退出 | 半透明卡片 + 柔光底 + 1dp 高光描边（不用实时模糊，零功耗）；`onClickOnce` 600ms 防抖治连点双开；ANR 根因是主线程解码音频 → 移后台；Android 12+ 后台起前台服务必抛异常 → 全 `runCatching` 降级；列表改 `GROUP BY` |
| v1.9 | 设置页写「支持说话人」，实际永远不触发 | 核对服务商真实响应（只返回 `{"text"}`）后把能力标记改为 false、纯文本服务不发扩展参数、400/422 自动降级重试、界面按真实能力禁用开关——**能力宣称与实际行为对齐** |
| v1.10 | 内页 logo 红压红看不见；切页、开详情慢 | 先垫白色磨砂圆（v1.22 已替换）；响应慢的真因在主线程：N+1 改一次 `GROUP BY`、Tab 改 add/hide/show 复用、长列表每 12 条一批 `addView` |
| v1.11 | 记录出不去、外部文字进不来 | 一份 Markdown 四处复用（导出 / 复制 / 微信 / 便签）；`ACTION_SEND` + `setPackage` 直达微信选聊天；`<queries>` 声明包可见性（漏了列表就是空的）；日历全天事件必须写 UTC 午夜；反向 `ACTION_SEND` 让外部文字落成记录 |
| v1.12 | 偶发错误日期；导入十几段就 429 | `SimpleDateFormat` 并发不安全 → `DateTimeFormatter`；注释写「串行」代码却并发 → `Mutex` 真串行；列表查询在 SQL 层 `substr` 截断；协程改 `lifecycleScope`；导出设 40 万字上限 |
| v1.13 | 手机丢了 / 截屏 / 云备份就把通话内容交出去 | Keystore 内 AES-256-GCM 加密 Key 与声纹（TEE 内、不随备份走、旧明文惰性迁移）；`allowBackup=false` + 数据提取规则；`FLAG_SECURE`；强制 HTTPS 双保险；锁屏通知 `VISIBILITY_PRIVATE`；剪贴板 `EXTRA_IS_SENSITIVE` |
| v1.14 | 装完还要在六七个服务商里挑 | 默认硅基流动（转写 + 摘要一套 Key），首次运行 seed 一次且不覆盖用户改动，**不内置 Key** |
| v1.15 | 戴耳机录很久，事后什么都没有 | 四条独立根因：通话静默抢麦无感知、单文件被打断即整段报废、解码失败被当成「没人声」删文件、只看开头 3 分钟就判死。修复：每 2 秒巡检 `AudioManager.mode`、连续 10 秒振幅为 0 判静音、打断即分段保存并自动续录、30 分钟定时切段、用 `analyzed` 区分「分析失败」与「没人声」、头中尾三点采样、启动时回收残留录音 |
| v1.16 | 想手动用手机麦，不想被耳机牵着 | 音源从藏起来的开关变成今日页可直接点；录音中切换走 `rotateSegment()` 先收尾再开新段，一句不丢；`startedByBluetooth` 区分自动触发与手动开始 |
| v1.17 | 钉钉闪记 / 飞书妙记 / 录音笔的内容进不来，草记也出不去 | 只走系统标准协议（三方私有目录读不到）：`ACTION_SEND` / `ACTION_VIEW` + SAF 多选；文稿跳过 ASR 直接入库；`TranscriptParser` 按说话人连读合并 cue、剔行内时间戳；出口三路（目录同步 / 一键复制 / Webhook），写入不删用户文件、不申请存储权限 |
| v1.18 | 想把记录推到飞书 / 钉钉群；设置页要滑三四屏找开关；缺法律声明 | 走**群机器人 Webhook**（自建应用要企业管理员，个人走不通）；两家签名的 key/data 与位置不同，逐字段解析业务码并翻成「下一步该改什么」；设置页 740 行扁平移成 5 张折叠卡 + 状态概览；12 章离线免责声明 + 反馈邮箱 |
| v1.19 | 说粤语按普通话认，满屏错字 | 先把边界说清（`wuu/nan/hak` 在 Whisper 协议里没有语言代码，传了只会 400）；`language` 参数化 + 四级降级链；繁转简用 OpenCC 一对一映射 3221 组，**故意排除一对多的字**（著 / 台 / 面 / 里 / 云 / 松 / 乾）；方言口语转书面语带长度畸变校验（<35% 或 >220% 退回原文）；事后方言检测给「一键按粤语重转」；热词表兜人名与公司名 |
| v1.20 | 项目经常归错，AI 分析不准 | 四条结构性根因（项目清单是模型输出的回声、只有名字没有特征、提示词鼓励硬填、输出无校验无纠正）。改造：`projects` 档案表（规范名 + 别名 + 线索词）、存量碎片自动归并、分析前按命中打分只给 ≤8 个候选、**强制抄原文证据并在代码侧回原文比对，抄不出就留空**、置信度 <0.6 标待确认、详情页可改并把上下文记成线索词、待办级项目归属 |
| v1.21 | 二十个版本连加功能，同一件事被写了好几遍 | 三维度扫描（零引用 / 重复块 / 未引用资源）：删 15 处死代码、收敛 13 处重复（会话写库 23 行、建表 DDL 两份会导致「新装正常、升级异常」、3 份取音频时长、5 个 OkHttp 实例）、4 处性能（档案缓存、归一化短词缓存、繁简短路、零宽字符一次遍历）；10 行重复块 21 → 0，告警 4 → 0。刻意不开混淆 |
| v1.22 | 内页 logo 读成「一条白线 + 一个内框」，红底上不立体 | 去掉所有托底，让标自己有体积：4 层同心缩放落影（矢量无 blur）、三段红渐变分受光与收暗、顶光 + 底压 + 只在上缘渐隐的边光；写 `render-vector.py` 解析 pathData 与渐变按同坐标渲染，按环带 72 个角度确认开口朝正右；导出 PNG/SVG 时投影改真高斯模糊（4 层叠在透明底上会露灰弧）、`feDropShadow` 不能挂在渐变填充的 path 上（会栅格化出色带） |
| v1.24 | 转写错字多，尤其远场和带口音时 | 主录音码率 64 → 96 kbps——此前只有它低于「长按语音」的 96 与声纹录入的 128，单声道 44.1 kHz 压到 64 kbps 相当于 11:1，辅音与气声先糊；默认识别语言 auto → 普通话，auto 在短句、口音、背景人声下会猜错语种，一旦猜错整段文字跟着走样；新增 Groq whisper-large-v3 预设，**换大模型才是错字率的最大杠杆**，录音参数只是把输入做干净 |

## 六、首次使用配置（必做）

### 1. 开启系统通话录音（OPPO/ColorOS）

设置 → 电话 → 通话录音 → 打开「自动录音」（可选「所有通话」）。
App 内「设置」→ **扫描系统通话录音并导入**，把已有通话录音纳入记录。

> 机型没有自动录音功能时，通话部分无法覆盖；现场对话不受影响。

### 2. 选 AI 服务商（App 内「设置」→ 只需填 Key）

地址和模型名都是**自动填好**的，你只需要：选服务商 → 填 Key → 点「测试连接」验证。

| 服务商 | 免费情况 | 推荐模型 | 备注 |
|--------|---------|---------|------|
| **智谱 GLM** | ⭐ **glm-4-flash 目前可免费调用** | `glm-4-flash` | 最省事的「真免费」选择，日常摘要够用 |
| **通义千问** | 新用户每模型 100 万 tokens 免费额度 | `qwen-turbo` | 阿里云百炼控制台申请 Key |
| **DeepSeek** | 无永久免费，单价极低（约 1~2 元/百万 tokens） | `deepseek-chat` | 中文摘要质量好，最推荐性价比 |
| **硅基流动** | 注册送额度，部分小模型长期免费 | `Qwen/Qwen2.5-7B-Instruct` | **转写也在这家**，一套 Key 全搞定 |
| **Kimi 月之暗面** | 有免费额度 | `moonshot-v1-8k` | 长会议记录友好 |
| **OpenAI** | 无免费 | `gpt-4o-mini` | 需要外币卡，国内可能要代理 |
| 自定义 | — | 任意 | 兼容 /chat/completions 的自建服务（one-api、Ollama、vLLM 等） |

**语音转写**同样是选服务商：

| 服务商 | 免费/价格 | 模型 | 说话人分离 |
|--------|----------|------|-----------|
| **硅基流动 SenseVoice** | 注册送额度、单价低 | `FunAudioLLM/SenseVoiceSmall` | ❌ 只返回纯文本（无 segments / speaker） |
| OpenAI Whisper | 按分钟计费，无免费 | `whisper-1` | ❌ 不返回说话人 |
| 自定义（Whisper 兼容） | 自建免费 | 自填 | 取决于服务（WhisperX / faster-whisper 可返回 segments 带 speaker） |

> 说明：说话人分离依赖服务端返回**带时间戳的说话人分段**。硅基流动官方响应只有
> `{"text": "..."}`，所以选它时 App 会关闭「说话人分离」并提示原因——
> 本机声纹比对同样靠分段切样本，没有分段就无法自动认出「我」。
> 需要「我 / 对方」区分时，改用自建 WhisperX / faster-whisper 一类的转写服务。

> 建议：**预算最省组合 = 硅基流动（转写）+ 智谱 glm-4-flash（摘要）**；
> 或者**一套 Key 全搞定 = 硅基流动（转写 + Qwen2.5-7B 摘要）**。

### 3. 测试连接

填完点「测试连接」：
- 成功 → 显示模型回复内容（说明地址、Key、模型名三者都对）
- 失败 → 明确提示问题：Key 无效（401/403）、地址不对（404）、额度用尽（429）、网络异常

### 4. 授权

首次进入会请求：麦克风、通知（Android 13+）、蓝牙连接（Android 12+）、音频/存储读取（导入通话录音）。

### 5. 记录音源：手机麦克风 / 蓝牙耳机麦

今日页底部「音源」行可直接切，与设置页的开关共用同一个偏好。

| | 手机麦克风（默认） | 蓝牙耳机麦克风 |
|---|---|---|
| 音质 | 44.1kHz | 蓝牙通话通路 8~16kHz，明显较低 |
| 距离 | 手机放桌上也能录 | 离嘴近，远处说话更清楚 |
| 对连接的影响 | 不动音频通路，最稳 | 会切 SCO，期间耳机音乐被打断 |
| 适合 | 会议、桌面、日常 | 走动、耳机一直戴着 |

> 耳机连接不稳时**保持手机麦克风**。录音中切换不会丢内容：当前段先收尾保存，紧接着用新音源开新段。

## 七、说话人区分与本人声纹

### 说话人区分：把「说话人N」换成「我 / 对方」

1. 「设置」→ 打开 **转写时启用说话人分离**（默认开）
2. 「设置」→ **我是说话人** 选择你在语音里对应的角色（说话人1 / 2 / 3 / 4）
3. 之后新转写的文本会变成这样：

```
[我] 3 号楼还剩 24 套，其中 8 套有客户在谈。
[对方] 那 10 月底之前能把意向金收一下吗？
[我] 可以，我这周跟进。
```

4. 大模型拿到带角色的文本后，摘要会明确区分「我承诺了什么 / 对方提出了什么」，洞察也按「我」的视角写。

> 说明：说话人分离能力取决于转写服务是否支持 diarization。
> - 支持（返回 segments/utterances 带 speaker）→ 自动标注说话人
> - 不支持（只返回纯文本）→ 自动降级为无角色文本，不影响其它功能
> 你只需要在设置里选一次「我是说话人几」，App 负责把标签换成「我 / 对方」。

### 本人声纹：自动认出「我」

设置 → 本人声纹 → 录入，朗读提示句约 15 秒（安静环境、手机离嘴 20~30cm）。此后录音在转写完成时自动判定，详情页显示「声纹：已自动识别 · 我 = 说话人1（匹配度 98%）」。

- 全部在本机完成，不联网、不上传声音；数据只在本地库，换机或卸载重装需重录
- 用的是 MFCC + 音高的轻量统计模型，不是深度学习声纹库：**男女声、音色差异明显的人分得准；同性别且音色接近的两人可能分不准**
- 把握不足时**不猜**：保留手动设置并标注「把握不足（匹配度 xx%）」，点一下改名后由 `SpeakerMap` 记住，之后同类说法自动沿用
- 依赖转写服务返回带时间戳的说话人分段；纯文本服务下自动跳过，界面会写明原因，声纹本身不用重录

## 八、待办到期提醒怎么用

1. 记录分析后，待办会自动带到期日（模型把「下周五」「月底前」这类相对时间换算成具体日期）
2. 「记录详情」里点某条待办下方的日期 → 可手动改到期日
3. 「觉察」页顶部会显示：今天到期 X 项 / 已逾期 Y 项
4. 「设置」→ **待办提醒**：可开关、可设每日提醒时间（默认 09:00）

提醒触发时机：
- 每日设定时间（AlarmManager，非精确闹钟，误差几分钟，无需特殊权限）
- App 每次启动时检查一次
- 新待办生成后立即检查一次

通知内容形如：**待办提醒 · 已逾期 2 项 · 今天到期 1 项**，正文列出前 3 条。

## 十一、已知限制与后续可做

**当前限制**
- 转写/摘要依赖网络与第三方 API（未配置时录音仍会保存，状态显示「待转写」，可稍后重试）
- **方言识别受限于服务端能力**：粤语可由 SenseVoice 原生识别；吴语 / 闽南语 / 客家话 / 湘语 / 晋语
  在 Whisper 兼容协议里没有对应语言代码，只能按普通话识别（App 会明确告知）。
  需要更强的方言能力，请用讯飞 / 通义听悟等专用接口转写后，把文稿导入草记
- 说话人区分需要**服务端返回带时间戳的说话人分段**。硅基流动 SenseVoice 与 OpenAI whisper-1 都只返回纯文本，
  选它们时「我 / 对方」不生效（App 会关闭开关并说明原因）；需要该能力请用 WhisperX / faster-whisper 一类的自建服务
- 通话录音导入依赖系统录音文件，且是**事后**导入（通话结束才有文件，非实时）
- 微信语音无法覆盖（系统限制）

**可以继续加**
- 本地说话人分离（切轮次 + 分段转写），让纯文本转写服务也能区分「我 / 对方」
- 端侧 whisper（离线转写，隐私更好，但包体大）
- 待办到期提醒的重复规则（如每周/每月）
- 多设备/多端同步（接 Supabase 或其他后端）
- 按月/按项目的复盘报告导出（PDF/CSV）
