# 草记手表端（安卓表 / Wear OS）

一块表上只做一件事：**忙的时候抬腕点一下，手机上就开始记录。**

录音、转写、摘要、上传全在手机上跑。这块表不碰麦克风、不存内容、不连服务器，
只在你按的那一下发几十个字节的指令——所以它的耗电约等于一块普通表盘。

包名 `online.wokaka.caojiwatch`，版本 `1.19.0w (1019000)`，minSdk 26 / targetSdk 33。

---

## 一、为什么是单独一个包

手机端是**鸿蒙**（同仓库 `harmony/` 目录，ArkTS + ArkUI），手表是**安卓**——两套系统、
两种技术栈，只能各出一个包。

更要紧的是：Wear OS 手表与 Android 手机之间的标准通道是 Google Play 服务里的
Wearable Data Layer（`MessageClient` / `DataClient`）。**鸿蒙手机没有 GMS**，
也装不了 Wear OS 配套应用，那条路在鸿蒙上根本不存在。

所以两端的通道是自建的：**同一 Wi-Fi 下的 UDP**。

```
手表 ──广播 {"c":"ping"}──▶ 255.255.255.255:47321
                              │
                         手机（草记）收到，记下来源地址
                              │
手表 ◀──单播 {"ok":true,"st":"rec","el":12000,"seg":1,"mk":2,"name":"P50"}──┘

之后：手表 ──{"c":"start"|"stop"|"mark"}──▶ 手机（直接单播到这个地址）
```

不用输入 IP、不用配对、不用账号：手表先广播，手机自己回，手表记住回包的来源地址。

---

## 二、怎么用

1. **手机**：草记 → 设置 → 录音与音源 → 打开「手表遥控（同一 Wi-Fi）」
   下面会显示一行地址，比如 `192.168.1.7:47321`（只是用来核对，手表不需要你输）
2. **手表**：装 `release/草记手表-1.19.0w.apk`，打开
3. 顶部出现「已连 手机名」就可以用了：
   - 点中间大圆钮 → 手机开始记录；再点一下 → 结束
   - 点「打点」→ 手机上留一个重点标记（和手机端点「标记」效果一样）
   - 长按顶部状态文字 → 重新找手机（换了 Wi-Fi、手机重启时用）

手机上如果还开着耳机自动记录，手表点「开始」和耳机连上是同一条链路，不会重复录。

## 三、耗电为什么低

| 手表端做的事 | 代价 |
|---|---|
| 只在界面可见时发心跳（3 秒一个包，几十字节） | 可忽略 |
| 退到后台立刻停 socket、放掉 Wi-Fi 锁 | 0 |
| 不开麦克风、不编码、不写盘、不上传 | 0 |
| 不注册传感器、不做常亮 | 0 |

对比「手表自己录音」那条路：麦克风 + AAC 编码 + 写文件，一小时能把小电池吃掉一大截，
而且手表麦克风离嘴远、录音质量差——录下来还得传回手机转写，绕了一大圈。

**已知代价**：手表和手机必须在同一个 Wi-Fi（手机开热点给手表连也行）。
手表为了省电会把 Wi-Fi 睡下去，所以进入界面的第一下可能要等 1~2 秒才连上；
这段时间界面显示「正在找手机…」，连上就变。

## 四、连不上怎么查

按这个顺序看，九成是第一条：

1. **同一个 Wi-Fi 吗** — 手机连着 5GHz、手表连着 2.4GHz 也可能算不同网络；
   很多路由器开了「AP 隔离 / 访客网络」，两台设备互相看不见，这种情况必须关掉
2. **手机端那个开关开了吗** — 设置 → 录音与音源 → 手表遥控。没开的话端口上没人监听
3. **手表的 Wi-Fi 真的连上了吗** — Wear OS 手表在手机旁边时常常自动关 Wi-Fi 走蓝牙，
   去手表设置里确认 Wi-Fi 是连着的
4. **想在电脑上验一遍**：跑 `python tools/probe-watch.py`，让电脑顶替手机。
   手表会连到电脑上，每条指令都会打印出来——能分清是「手表没发出去」还是「手机没回」。
   Windows 防火墙第一次会问，**必须允许**，否则包进不来

## 五、工程结构

```
watch/                              （仓库子目录）
├── app/src/main/
│   ├── AndroidManifest.xml          只要网络权限；声明 watch 属性但不强制
│   ├── java/online/wokaka/caojiwatch/
│   │   ├── MainActivity.kt          一屏三件东西：大圆钮 / 打点 / 状态
│   │   └── WatchClient.kt           UDP 广播发现 + 单播指令 + 心跳
│   └── res/
│       ├── layout/activity_main.xml 圆形表留了 26dp 左右边距
│       ├── drawable/bg_btn_*.xml    空闲是黑底红边，录音中是红底
│       └── values/                  文案
└── tools/probe-watch.py             联调工具：在电脑上假装自己是手机
```

侧载包不进源码库（避免仓库逐版本膨胀），统一放
[Releases · v1.19.0w](https://github.com/sansimon2001/CAOJ/releases/tag/v1.19.0w)，
文件名 `caoji-watch-v1.19.0w.apk`（debug 签名，开了 R8，约 1.5 MB）。

## 六、怎么装到手表

侧载（Side-load），三条路任选：

**A. 手表开发者模式 + adb（最稳）**

```bash
# 手表：设置 → 关于 → 连点版本号 7 次 → 开发者选项 → 打开「ADB 调试」和「Wi-Fi 调试」
adb connect <手表IP>:5555
adb install -r caoji-watch-v1.19.0w.apk    # 从 Releases 下载的包
```

**B. 手机助手**：小米/华为/OPPO 各自的手表助手 App 里通常有「安装本地应用」

**C. 蓝牙 ADB**（部分表支持，速度慢）

装完在表盘应用列表里叫「草记手表」（红色圆点图标）。

## 七、重新打包

```bash
cd watch
JAVA_HOME=/c/Users/simon/.workbuddy/binaries/jdk17/jdk-17.0.20.1+1 ./gradlew --offline assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

依赖刻意只用本机缓存里有的那几件，`--offline` 也能出包。三处踩过的坑写在
`app/build.gradle.kts` 的注释里（coroutines 要抬到 1.8.1、appcompat 要不带 material
就会去够没缓存的 drawerlayout 1.0.0）。
