# 草记 · PC 端

手机端录不到的东西，这里能录；录完还得整理得动，所以这一版把「导入 → 转写 → 归类 → 纪要 → 方案 → 日程」整条串起来了。

腾讯会议、飞书会议、Zoom、微信语音、网课 —— 这些声音从扬声器出来，手机没有权限去采，
行业里所有录音 App 在安卓和 iOS 上都做不到。PC 端走 WASAPI 回环，可以直接把系统输出的声音录下来，
还能和麦克风混成一条轨，线上会议双方都清楚。

**这个能力已实测验证，不是假设。** 见 [`spike/`](spike/README.md)：程序自己播一个 1 kHz 正弦波，
再从回环录回来分析频谱 —— 基线能量 0，信号期峰值 255（满量程）。同一套代码录静音时 RMS 是
0.000005、峰值 0，说明拿到的不是一段静音空包。

## 二、怎么跑起来

```bash
cd pc
npm install

# 开发（带热更新）
npm run dev

# 生产模式：编译主进程 + 打包前端 + 启动
npm start

# 只重新构建
npm run build
```

> 如果启动时报 `Cannot read properties of undefined (reading 'commandLine')`，
> 说明环境里被注入了 `ELECTRON_RUN_AS_NODE=1`，Electron 退化成了纯 Node。
> `tools/launch.js` 已经处理了这种情况，直接用 `npm start` 即可。

### 技术栈

| 项 | 值 |
|---|---|
| 外壳 | Electron 31 |
| 渲染层 | React 19 + TypeScript + Vite |
| 录音 | Web Audio + MediaRecorder（Opus 96 kbps） |
| 长音频切片 | 渲染进程 `decodeAudioData` + `OfflineAudioContext` 重采样，产出 16 kHz 单声道 WAV |
| 时长探测 | music-metadata（CommonJS 版，主进程直接 require） |
| 转写与摘要 | 直连 HTTP，无中间服务 |

## 三、长音频为什么要切片

转写服务普遍限制单次 25 MB / 若干分钟，而一小时 mp3 就有几十 MB，整段上传不是被拒就是超时。

项目里**没有引入 ffmpeg**（不想为了转写多背 80 MB 二进制），借的是 Chromium 自带的解码器：

```
音频文件 → decodeAudioData 解出 PCM
        → OfflineAudioContext(1 声道, 16 kHz) 一次性降混 + 重采样
        → 按 5 分钟切段，编码为 16 bit WAV（一段约 9.6 MB）
        → 逐片送 ASR → 按顺序拼接 → 生成带时间点的章节索引
```

16 kHz 单声道正好是 32 KB/秒，5 分钟一段稳稳落在各家限制内；
而 Whisper / SenseVoice 内部本来就按 16 kHz 单声道处理，音质上不吃亏。

**兜底**：解码失败（格式特别、文件损坏、超长）时自动退回整文件上传；
中途某一片失败会保留已完成的部分，并提示第几段出错，不会把已花的转写费白扔。

**上限**：解码要把整段 PCM 装进内存，超过 3 小时的音频会被明确拒绝并提示先切分，
而不是把渲染进程撑爆。

## 四、填一次 Key 就能用

打开「设置」，转写和大模型各选一家。地址与模型名已按服务商预填好，通常**只需要填 Key**。
默认是硅基流动：转写与摘要同一家、同一套 Key，注册送额度。

| 环节 | 推荐服务 | 说明 |
|---|---|---|
| 转写 | 硅基流动 SenseVoice | 便宜、中文好；只返回纯文本 |
| 转写 | Groq Whisper large-v3 | 最准，远场与口音场景错字明显更少；需能访问境外服务 |
| 摘要 / 纪要 / 方案 | 硅基流动 Qwen2.5-7B | 与转写同一套 Key，最省事 |
| 摘要 / 纪要 / 方案 | 智谱 glm-4-flash | 目前可免费调用 |

填完点「测试连接」，会真的发一次最小请求 —— 成功会回显模型说的话，
失败会明确告诉你是 Key 无效、地址不对还是额度用尽。

Key 存在本机，落盘前用系统级加密（Windows 走 DPAPI），换机器要重填。

## 五、录音与导入

| 音源 | 适合 | 说明 |
|---|---|---|
| 麦克风 | 线下见面、当面沟通 | 普通采集 |
| 系统声音 | 腾讯会议 / 飞书 / 微信语音 / 网课 | WASAPI 回环，电脑在放什么就录什么 |
| 两者都录 | 线上会议 | 你的声音走麦克风，对方的声音走回环，混成一条轨 |

混音时麦克风开了回声消除：系统声音已经由回环单独录了一份，如果麦克风再把扬声器漏出来的声音
收进来，同一句话会出现两遍还带时间差。

**系统声音录不到内容时先查三件事**：声卡在不在放声音、系统音量是否为 0、有没有插着耳机但
播放设备选的是另一个。回环采的是「默认输出设备」，设备不对时录到的就是静音。

导入的文件会被**拷贝**进数据目录 —— 原文件删了也不影响记录。
字幕文件（srt / vtt / lrc）会剥掉序号与时间轴，只留台词，并把被字幕拆碎的句子拼回去。

## 六、整理与分析分别做什么

| 按钮 | 做什么 | 边界 |
|---|---|---|
| 整理文字 | 规则清洗：去句首语气词、去 `[音乐]` 类噪声、压叠字、统一中英标点、每 4 句分段 | 不改一字原意，纯机械 |
| AI 精修文字 | 让模型断句、去口头禅、改明显同音错字 | 长度变化超出 70%~135% 直接放弃精修，避免被改写 |
| 生成纪要 | 议题 / 结论决议 / 行动项（含负责与截止）/ 分歧风险 / 下一步 | 只写原文有的，说话人分不清就写「会上」 |
| 生成方案 | 目标 / 4-7 步 / 负责与时间 / 需要什么 / 风险 / 验收标准 | 信息不足时写「需确认：xxx」，不编数字 |
| 重新整理 | 摘要、待办、洞察、类型、标签、项目归属 | 已手动指定过项目的，不会被覆盖 |

**原文永远不动。** 整理稿单独存一份，导出时可对照原始转写。

### 出口校验不是摆设

模型会编数字、编待办。每次整理完都过一遍规则校验：

- 摘要里的数字、金额、日期必须能在原文里找到，找不到超过一半就标「需人工确认」；
- 待办必须有原文依据，对不上的直接丢弃，并告诉你「已过滤 N 条」；
- 摘要与原文重合度过低会提示（这条对**短文本跳过** —— 几百字的原文，摘要天然是改写，
  照搬阈值只会把好摘要标红）。

被过滤掉的待办会写进记录的校验说明里显示出来，不会静默消失。

## 七、项目归类怎么判断

建好项目档案（名称 + 别名 + 线索词）后，整理时按三步归：

1. 先看模型给的项目名，**且它引用的原文片段必须能在原文里逐字找到** —— 编的引用一律作废；
2. 模型没给或证据对不上，退回本地打分：规范名命中 ×3、别名 ×2、线索词 ×1，同一个词重复出现不叠加；
3. 置信度落库，界面上写明「自动归属依据：……」，随时可以改成别的项目。

手动指定过的记录置信度记为 1.0，之后重新整理不会被 AI 覆盖。

## 九、数据在哪

```
%APPDATA%/caoji-pc/
├── settings.json          配置（Key 已加密）
└── data/
    ├── records/<id>.json  一条记录一个文件
    ├── audio/<id>.<ext>   对应音频
    ├── projects.json      项目档案
    └── events.json        日程
```

设置页有「打开数据目录」。整个 `data/` 拷走就是完整备份，换机器放回同一位置即可。

选这个存法而不是 SQLite，是因为逐条写文件不会出现「写到一半断电，整个库都坏了」，
单条损坏最多损失一条。记录量到几千条时再换库也不迟，结构已经是平的。

## 十一、怎么验证它真的在工作

脚本都在页面上下文里跑，由环境变量注入：

```bash
# 1) 可行性：播 1kHz，再从回环录回来分析频谱
npm run spike

# 2) 录音链路：自动点开始、录 4 秒、点结束，核对记录是否落盘
CAOJI_E2E="$(pwd)/tools/e2e-record.js" node tools/launch.js

# 3) 解码核对：把录到的 webm 真解码，算 RMS 与峰值（判断是不是静音空包）
CAOJI_E2E="$(pwd)/tools/e2e-decode.js" node tools/launch.js
```

完整链路（导入 → 切片转写 → 分析 → 纪要 → 方案 → 导出）用本地模拟服务验证，不需要真 Key：

```bash
node tools/mock-ai.js &
CAOJI_E2E="$(pwd)/tools/e2e-full.js" node tools/launch.js
```

它会把外部服务全换成 `tools/mock-ai.js`，但内部走的是真实的 IPC、真实的切片代码、
真实的 JSON 解析与出口校验。**26 项断言全部通过**，覆盖：

- 6.5 分钟音频被切成 **2 片**、逐片送 ASR、拼接结果含两段、生成 2 条章节索引；
- 摘要 / 纪要 / 方案三个产出都能解析入库；
- 模型给出「原文没有的数字 + 编造的待办」时，守卫确实拦下（`needsReview` 为真、待办被清空）；
- 项目归属取到原文证据、置信度是 0.9 而不是硬编码的 1。

另外 `CAOJI_SHOT=<png 路径>` 可以让程序加载完界面后自动截图再退出，
配合 `CAOJI_SHOT_CLICK`（CSS 选择器或 `js:` 开头的一小段脚本）与 `CAOJI_SHOT_SCROLL`（像素）
可以截到指定视图与滚动位置。

## 十二、已知限制

- **没有安装包**。要从源码跑（`npm start`）。要发给别人用，还需要接 electron-builder 出 exe。
- **没有与手机端同步**。目前只能导出 Markdown / HTML 手动搬。
- **docx 导出没做**。HTML 那份已经排好版，浏览器打开后「打印 → 另存为 PDF」即可，
  中文不掉字、表格与标题层级都保得住。
- **超过 3 小时的单个音频不切**。解码要把整段 PCM 装进内存，会被明确拒绝并提示先切分。
- **没有静音检测**。录一场没人说话的会照常保存。
- **说话人分离依赖服务端**。SenseVoice 与 OpenAI whisper-1 都只返回纯文本，
  所以没有做「我 / 对方」的区分。
- **方言受服务端限制**。粤语 SenseVoice 原生支持；吴语、闽南语、客家话等在 Whisper 协议里
  没有对应语言代码，只能按普通话送，App 不会假装支持。
- **系统声音需要默认输出设备在放声音**。用独占模式的播放器时可能采不到。

## 十三、合规

录音涉及他人声音。会议录音前请告知参会人，仅作个人工作记录使用，
不要用于非法目的或公开传播。系统内录同样受此约束 —— 能录不代表可以随便录。
